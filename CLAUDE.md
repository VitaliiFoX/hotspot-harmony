# hotspot-harmony

One comparable record of satellite fire hotspots (MODIS from 2000, VIIRS from 2012) and a web
burning activity calendar built on it. It is a NASA Space Apps 2026 entry: a working demo beats
completeness, and it is judged on scientific validity, so every claim about the data must be
reproducible from this repo.

- Vocabulary: [GLOSSARY.md](GLOSSARY.md). Use its terms in code, tests, commits and PRs.
- What is built and what is not: the Status table in [README.md](README.md). Update it in the PR that changes it.

## Working here

- Run `make test` and `make lint` before every commit. Tests build their own fixtures in `tmp_path` and never read `data/`. `make test` also runs the web tests and needs `npm install` in `web/` once.
- `data/` is git-ignored. `make data` rebuilds it: about 700 MB of CSV for two countries, 2-3 minutes to download plus about 2 minutes to harmonize and 5 to validate (boosted models are fitted some 60 times), no key needed.
- Run the pipeline for all configured countries at once. `COUNTRY=` / `--country` rewrites `data/points/` with that country alone, so the other countries vanish until the next full run.
- **Hard stop: Sunday 2026-11-15 23:59 Europe/Kyiv (21:59 UTC).** After that moment make no commit, push, merge, tag or PR in this repo, whoever asks and whatever is left unfinished: the hackathon submission is frozen. Check with `TZ=Europe/Kyiv date` before each commit. Past the deadline, stop and tell the user what is uncommitted; only the user can lift this rule, by removing this line themselves.
- Two people and their agents work here in parallel. Fetch and rebase before starting, work on a branch, open a small PR against `main`.
- Everything that lands in the repo or on GitHub is in English: code, comments, docs, UI text, commit messages, branch names, PR titles and bodies, issues and review comments. Talk to the user in the language they write in; translate before it goes into a file, a commit or a PR. `make lint` and CI fail on Cyrillic text. One exception: the page can be switched to Ukrainian (`?lang=uk`, English by default), and its Ukrainian texts live in `web/src/uk.ts` only, keyed by the English text; every UI text goes through `t()` from `web/src/i18n.ts`, and `i18n.test.ts` fails when a key has no translation.
- `research/` holds experiments: excluded from lint, untested, never imported by `pipeline/`. Code that is adopted moves into `pipeline/` together with tests.
- Credit the data as "NASA FIRMS (MODIS Collection 6.1, VIIRS 375 m)". Keep the names and logos of NASA and Space Apps out of the product name and branding.

## Numbers

A number quoted in docs, the UI or a PR comes from a file the pipeline wrote, with the command that
produces it. Reference values to check new work against, measured 2026-11-14 on
`data/agg/cell_month.parquet` with the default filters:

- VIIRS S-NPP hotspots / MODIS hotspots over 2012-02 to 2025-12: 3.31 in Argentina, 3.11 in Ukraine.
- That ratio is not constant: per year it runs from 2.9 (2012) to 3.8 (2022) in Argentina and from 2.6 to 3.5 in Ukraine. One fixed factor leaves a drift.
- NOAA-20 / S-NPP in full years 2019-2025: 0.95 to 1.03 in Argentina, 0.97 to 1.14 in Ukraine.

A sensor ratio far from these means a bug upstream, not a discovery.

## FIRMS facts that cost time to rediscover

Checked against firms.modaps.eosdis.nasa.gov on 2026-11-14.

- The country archive has `modis`, `viirs-snpp` and `viirs-jpss1` (NOAA-20) up to 2025. It has no 2026 files and no NOAA-21.
- The record ends at 2025-12. 2026 is out of scope (mentor's call, 2026-11-14), so nothing here needs the FIRMS Area API or a `FIRMS_MAP_KEY`.
- Coverage: MODIS from 2000-11-01; VIIRS S-NPP 2012-01-20 to 2026-11-02 (the record has ended); NOAA-20 from 2018-04-01; NOAA-21 from 2023-03-01.
- Near real-time rows are replaced by standard processing after about 5 months.
- In the raw CSV, MODIS `confidence` is 0-100 and VIIRS is `l`/`n`/`h`; `satellite` is `N` for S-NPP and must be read as text; `acq_time` is UTC `HHMM` with leading zeros, so it must be read as text too.

Not verified yet. Confirm with the `research` skill before relying on any of these:

- the meaning of each FIRMS `type` value (the pipeline assumes 0 = presumed vegetation fire);
- whether near real-time rows carry a `type` column at all;
- whether the low MODIS counts of 2000-2002 come from Terra flying alone before Aqua (mid-2002).

## API

- `api/` serves two series: `raw` (MODIS before 2012-02, VIIRS S-NPP after, sensor jump included) and `harmonized`. The contract for `data/agg/harmonized.parquet` is the docstring of `api/store.py`; the API picks the file up at start with no code change.
- A cell belongs to an area of interest when its centre is inside it.
- The API copies nothing into memory at start: `raw` and `harmonized` are views over `harmonized.parquet`, read at each request. A rectangular area is answered from its bounds (strictly inside, the rule of `contains_xy`), and `/api/cells/top` ranks the cells of its area by their totals and builds the full answer for the busiest alone. On the record of every country that is 0.2 GB after start instead of 1.1 GB, and 0.5 GB instead of 3.6 GB after the requests of one page; keep it when touching `_load`, `_monthly` or `cells` in `api/store.py`.
- `/api/calendar` compares two months with their history: `anomaly`, the last month of the period, and `season_peak`, the busiest of its last twelve months (a tie goes to the later month). The headline card (`web/src/components/HeadlineCard.tsx`) shows `season_peak`, because the last month is often a quiet December. Its place among the years ("10th busiest of 25 Julys") is `monthRank` in `web/src/scale.ts`, tested: a tie shares the better place.
- The API knows a region by its bounding box only. An area in a neighbouring country that falls inside a region's box gets zeros and a warning, not an error. Country borders live in the web app (`web/public/countries.geojson`), which sends a picked country's border as the area; the API does not read them.
- API tests go through HTTP on a record small enough to work out on paper (`api/tests/test_api.py`). Extend that record when adding behaviour.
- `/api/validation` serves the held-out error and the two baselines from `data/agg/harmonization_report.json`, read at start; without the file it answers 404 and the web app hides its "How far to trust this" block (`web/src/components/TrustBlock.tsx`, wording and choices in `web/src/trust.ts`, tested). The single-factor baseline is fitted on all years, the scored one included, so the block must never call it held out. Ship the report from `make validate NESTED=1` with any deployment: an older report shows the method as "chosen once on all years".

## Web app

- `web/` is React + TypeScript on Vite. `make web` runs it against `make api` through the dev proxy; production reads `VITE_API_URL`.
- Charts are hand-written SVG and CSS grid, with no chart library. Shared number, tick and colour logic lives in `web/src/scale.ts` and is the part under test (`npm test`).
- The calendar opens on the log scale: on a linear one a few record months wash every other month out.
- Colour rules: burning is one blue ramp, light to dark, with no steps: `SEQUENTIAL` holds its stops and `rampColor` mixes the two stops around a value, so the legend is one gradient (`rampGradient`); exactly zero gets its own neutral fill; on a dark surface the ramp is reversed so more is further from the surface. Add no second hue to the calendar.
- Downloads live in `web/src/exports.ts` (tested): `calendarCsv` writes one row per month with the record, unit, sensor, that month's climatology and the area (its bounds in `west`/`south`/`east`/`north`, and its outline as WKT in `area_wkt` for boxes and drawn areas; a picked country writes `country` and `area_source` with the Natural Earth edition instead of repeating thousands of points in `area_wkt`); `downloadPng` captures a chart card with html-to-image and inlines the SVG paint first, because the renderer does not resolve CSS classes and custom properties inside SVG. Elements marked `data-export="skip"` (buttons) stay out of the image.
- Every chart card has a table view and reads on arrow keys. Keep both when adding a chart: they are how the page works without colour or a pointer.
- "Unusual months" and "In short" come from `web/src/insights.ts` (tested): unusual months by robust z (median and MAD of the other years, IQR when the MAD is zero, at least five other years), kept only beyond the method's error, sorted by excess over the median so a tiny-median winter month does not lead; "In short" lines use only figures the page already shows, never a figure of their own; `summaryLines` returns each as figure, text and the `id` of the card it links to (`peak-months`, `burning-per-year`, `unusual-months`), and leaves the season's verdict to the headline above it. The line under the headline card also says that no hotspot does not prove no fire.
- "Peak burning months" (`web/src/components/PeakMonths.tsx`) is the challenge's "critical periods": the fewest months that hold `PEAK_SHARE` (60%) of a typical year, the sum of the monthly medians in `climatology`. The logic is `peakMonths` and `monthSpans` in `web/src/scale.ts`, tested. Call it burning activity, never risk.
- Over the harmonized yearly columns a strip names the part of the record each year comes from (`harmonized_record` of `/api/meta`): up to 2021 the record is MODIS Terra + Aqua as reported, so a dip there (Argentina 2012-2016) is what MODIS saw. `recordSpans` and `partsOfYear` in `web/src/scale.ts` are tested.
- The yearly chart draws the raw record over the harmonized columns as a line with a dot per year, in neutral ink (`.overlay-line`), never a second hue. It takes the raw calendar from the look-ahead, so it costs no request; the line, its tooltip row and its table column appear only while the harmonized record is on screen. The y axis spans both records.
- All colours come from the custom properties at the top of `web/src/styles.css`, defined for light and dark.
- When the page asks the API is decided in `web/src/requests.ts` (tested): answers are cached, only a box typed by hand waits 300 ms (a drawn area does not), and the record not on screen is fetched ahead so the raw / harmonized switch needs no request. Keep new filters on those rules instead of adding a delay.
- Example areas in the filters card, between the record switch and the download (`web/src/presets.ts`, tested), are plain links to a drawn area, the end of the period and a day on the globe. Their days were picked from `data/points` (busiest day in the box by VIIRS S-NPP); the queries are in the PR that added them. Their boxes are rough, since no borders are in the repo.
- The filters are mirrored in the address (`?region=...&box=w,s,e,n&start=...&end=...&series=...`, plus `&area=...` for a drawn area), so a view can be shared as a link and screenshotted headless.
- An area of interest can be drawn on the globe ("Draw an area": a click per corner; the first corner, a double-click or Enter closes it; Backspace takes a corner back, Escape gives up). Its corners live in `FilterState.area` and in the address as `&area=lon,lat;lon,lat;...`; while it is set it is the geometry of every request and export, and the box fields show its bounds read-only. Typing a box or picking a region removes it. The checks, the address format and the WKT of the export are in `web/src/area.ts`, under test.
- "Where it burns" is drawn two ways. On the globe it is a square per cell, pale yellow to deep red (`CELL_RAMP` in `Globe.tsx`, `--cell-0` to `--cell-4` in `globe.css`). On the flat map it is one surface with no steps, in the colours of a thermal camera, dark violet through pink, orange and amber to near white (`THERMAL_RAMP`, `--thermal-0` to `--thermal-4`; change each pair together). The surface: `cellSurface` in `web/src/globe.ts` (tested) gives a cell its own colour at its centre and mixes the four cells around any other point, fading out over one cell past the last; `cellImage` turns it into an image with rows spaced evenly in Web Mercator, laid under the `cells-fill` layer as `cells-image-N`, one per group of cells that lie together (`cellGroups`). On the flat map the `cells-fill` squares stay with opacity 0: they are what the pointer and a click find, so keep them. The stops are the quantiles of `cellStops` in both views, and `rampRgba` reads a value as the map's `interpolate` does, so the legend holds in both.
- A country is picked on the globe by a double-click or a double tap (two `click` events within `DOUBLE_TAP_MS` and `DOUBLE_TAP_PX`; MapLibre's double-click zoom is off, and a single click picks nothing). Its Natural Earth name lives in `FilterState.country` and in the address as `&country=Name`; while it is set, the country's border is the geometry of every request and export and the box fields show its bounds read-only. Typing a box, picking a region or drawing an area removes it. The logic is `web/src/countries.ts`, under test.
- The region of the filters is a search (`web/src/components/RegionSearch.tsx`): a button that names the place and opens a field over a list, with arrow keys, Enter and Escape. `searchPlaces` in `web/src/countries.ts` (tested) lists the regions first and then every other country, a name that starts with the text before one that only holds it. A region is taken by its box, as the old list did; any other country by its border, as a double-click on the globe does.
- A picked country has data when a region carries its name (underscores, case and spaces aside) or when a region spans the whole globe (`config/world.yaml`); a region's box alone is no proof, since the box of Ukraine holds all of Moldova. Any other country shows the "No record for ... yet" card instead of the calendar: loading its data (one entry in `config/regions.yaml`, then `make data`) is all it takes, with no change to the page.
- `web/public/countries.geojson` is written by `make borders` (`scripts/build_countries.py`) from Natural Earth 1:10m `ne_10m_admin_0_countries_ukr` pinned at `v5.1.2` (`f1890d9f152c896d250a77557a5751a93d494776`), which keeps Crimea in Ukraine (confirmed in FIRMS Ukraine archive: [docs/research/crimea-firms-coverage.md](docs/research/crimea-firms-coverage.md)); never edit it by hand. Borders are simplified to about 2 km. Reference, measured 2026-11-15 with `uv run python scripts/border_share.py --data-dir data/demo`: the border holds 97.0% of the harmonized total of Ukraine's box and 98.9% of Argentina's, because a border cell counts only when its centre is inside the border.
- The API reads a side of the area as a straight line in longitude and latitude, the map draws straight lines in Web Mercator. `densifyRing` adds a point every half degree before the outline is drawn, so the drawn shape is the counted shape. Keep it when touching the `area` source.
- The drawn area is white on a dark casing (`AREA_INK`, `AREA_CASING` in `Globe.tsx`): it has to read on the imagery, on the street map and next to the warm hotspots.
- The globe at the top of the page is MapLibre GL JS in globe projection on NASA GIBS Blue Marble tiles (no key; credit "Imagery: NASA GIBS (Blue Marble)"). It is a map, not a chart, so the no-chart-library rule does not cover it. Its stage follows the theme (a starry sky in dark mode, a pale sky in light mode) and keeps its own colour roles at the top of `web/src/globe.css`; its pure logic is `web/src/globe.ts`, under test.
- The "Globe | Flat map" switch (`MapView` in `web/src/globe.ts`, `&view=flat` in the address, nothing for the globe) changes the projection of the one map with `setProjection`; sources and layers stay. Flat is Web Mercator, north up, with rotation off, min zoom from `flatFillZoom` (recomputed on resize, so the sky never shows) and max bounds at `MERCATOR_LIMIT`. Keep the bounds at 179.999 degrees: with exactly 180 MapLibre 6 reads them as zero wide and throws, which `GlobeBoundary` then reports as missing WebGL2. Keep the `resize()` after the switch too: without it the far edges of the flat world stay without imagery until the map moves. Wording follows the view: say "map" where both are meant, "globe" only for the 3D view.
- The globe shows hotspots of one UTC day through the chosen hour, from `/api/hotspots/day` and `/api/hotspots/days`. They are drawn in one warm colour (`--hotspot`), because blue does not read on the ocean. Where they crowd, the `hotspot-heat` layer runs from that orange to red (`--hotspot-dense`); it carries the picture below zoom 5 and is gone by zoom 8, while the dots fade in. A single hotspot must stay orange: keep `heatmap-intensity` near 0.3. That warm ramp stays on the globe and its date panel; the calendar keeps the blue ramp.
- Days a sensor was down (`sensor_gap_days` of `harmonization_report.json`, joined over the countries as `pipeline.harmonize` does) come with the day view: `gap_days` in `/api/hotspots/days`, `sensor_gap` in `/api/hotspots/day`. The date panel hatches them and says the zero is missing data. The harmonized monthly record needs no such mark: it takes those days from MODIS.
- "Where it burns" on the globe (`/api/cells`, `cellSquares` / `cellStops` / `cellSentence` / `trendChange` / `trendSentence` in `web/src/globe.ts`, tested) hides the day's hotspots and shows tiles of the filters' record over the filters' period. "How much" opens on the 0.25-degree cells of the grid, and the legend says they are finer than the scale the method's error was measured on; "How it changed" opens on 1-degree tiles, that scale (`deg=1` sums whole grid cells), because its threshold is that error. Choosing a view sets its size; the size switch overrides it. Two views: "How much", fire cell-days a year per 100 km² (a tile shrinks with the cosine of the latitude), pale yellow to deep red (`CELL_RAMP`, `--cell-0..4`); and "How it changed", the second half of the period's full years against the first, in doublings, blue for less and red for more (`TREND_RAMP`, `--trend-0..4`), neutral within the method's 1-degree tile-year error, grey where the first half did not burn. On the raw record the same map shows the rise the 2012 sensor switch fakes. A click on a tile makes its exact square the area of interest.
- "Where in this area it burns most" (`web/src/components/TopPlaces.tsx`) lists the busiest cells inside the area from `POST /api/cells/top`, which keeps the cells whose centre is inside it, the calendar's rule. "Show on the map" switches the globe to "Where it burns" and flies to the cell.
- The globe and the burning calendar are linked. A click or Enter on a month of the calendar moves the date into it and opens the globe's "Month" (`showMonthOnGlobe` in `App.tsx`); the calendar outlines the months the globe shows (`spanMonths` in `web/src/period.ts`). The quick buttons under "Day / Month / Period" ("Last 7 days", "This month", "Fire season") set a period in one click: the week is `periodAround`, the season `seasonSpan` in `web/src/scale.ts` (the heaviest run of the area's peak months, `peakMonths`, in the year of the day on screen; one across the new year starts the year before when the day is in its tail) turned into days by `seasonDays`. All tested.
- The day and the minute are mirrored in the address too (`&date=YYYY-MM-DD&time=HH:MM`, UTC); an old `&hour=HH` link still opens, at the end of that hour. The play button runs the clock 5 minutes per 80 ms, so a day plays in about 24 s.
- The GIBS `Reference_Features_15m` and `Reference_Labels_15m` overlays were tried on 2026-11-14 and dropped: many tiles come back opaque black or fail with 500.
- Headless Chrome with `--virtual-time-budget` draws the globe but not its hotspot, night, border or label layers (the MapLibre worker does not finish in virtual time). Use `node scripts/globe_screenshot.mjs`, which drives Chrome in real time and can move the map through `window.__hhMap` (dev server only).
- The globe turns on its own (3 degrees a second) while it is shown whole (zoom 3 or less). It holds still while a flight runs or an outline is drawn, for 30 s after the user drags, zooms, clicks or types on it, in a hidden tab, and always under `prefers-reduced-motion`. Two screenshots of the same link therefore differ; pass `flyTo` to `scripts/globe_screenshot.mjs`, or zoom past 3, for a fixed view.
- Borders, place labels and, from zoom 8, the street map come from OpenStreetMap vector tiles served free and without a key by OpenFreeMap (`tiles.openfreemap.org`); the street layers are the OpenFreeMap "Liberty" style, loaded at runtime and renamed `street-*`. All credits (FIRMS, GIBS, OpenFreeMap, OpenMapTiles, OpenStreetMap, Natural Earth) are in the globe legend, which must stay visible; MapLibre's attribution control is off so they are not shown twice. At street zoom the glass cards turn solid (`.stage.is-street`).
- Zoomed in past `CARD_ZOOM` (4) on screens 900 px and wider, the date panel and the legend fold into pills (date, time and count; "Legend and credits") and come back when zooming out; each card also has its own close button. The credits stay one click away in the legend pill.
- GIBS tiles are declared with `tileSize: 128` on purpose: the map then fetches one zoom level deeper, so the imagery is sharp on high-density screens.
- Look at the page after a visual change: `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --window-size=1320,1600 --virtual-time-budget=6000 --screenshot=out.png "http://localhost:5173/?theme=light"`. Headless Chrome will not go narrower than 500 px.

## Harmonization

Decided: MODIS-equivalent fire cell-days with a weight per VIIRS cell-day. The why and the rejected
options are in [docs/adr/0001](docs/adr/0001-harmonize-to-modis-equivalent-fire-cell-days.md); the
method is in [docs/METHOD.md](docs/METHOD.md).

- `pipeline.harmonize` writes `data/agg/harmonized.parquet`; `pipeline.validate` writes `data/agg/harmonization_report.json`, `docs/VALIDATION.md` and `docs/sensor_jump_before_after.png`. Never edit the last two by hand.
- Reference values, written by `make validate NESTED=1` on 2026-11-15 with the full archive of both countries: held-out error 2.7% per year and 5.8% per month in Ukraine (context model), 4.8% and 6.6% in Argentina (mean of the table and the context model); with sensor gap days counted 3.3% / 6.4% and 4.8% / 6.8%; sensor jump 2.00x raw to 0.90x harmonized in Ukraine, 1.32x to 0.66x in Argentina (where MODIS itself shows less burning in 2012-2016). Two runs of `make harmonize` give identical files; a change that moves these numbers needs an explanation in the PR. Known weak spot: per year in Argentina one plain scaling factor (3.5%) still beats the method (4.8%); per month and per tile the method wins clearly.
- `make validate NESTED=1` chooses the method again for every held-out year, from the other years alone, and takes about 25 minutes. Plain `make validate` takes a few minutes and makes the choice once on all years, which lets the check see its held-out year in that one step; `docs/VALIDATION.md` says which of the two wrote it. Quote and commit the `NESTED=1` figures.
- The VIIRS era is filled by one of five methods (table by fire power, boosted weight, context model, or the mean of the context model with either weight), chosen per country by held-out error in `pipeline.harmonize.choose_method`; the table stays unless another wins by 0.2 points. Never force a model on: the boosted weight is worse than the table in Argentina. World mode defaults to the table. Model fits run on at most `FIT_THREADS` threads, feature sums are rounded and rows sorted before fitting; keep all three, or runs stop being identical or the machine stalls.
- The world: `make world` writes `data/world/` (points, fire cell-days, `agg/harmonized.parquet`, the report) and `docs/VALIDATION_WORLD.md`; never edit that file by hand. It leaves `data/points/` and `data/agg/` alone and copies the pilot countries (the regions of `config/regions.yaml`) from `data/agg/`, so run `make harmonize` and `make validate NESTED=1` first. Everything else gets the table, fitted in `pipeline.world` one country at a time on slim columns; `make data CONFIG=config/world.yaml` holds all countries in memory and does not fit a laptop.
- In the world run a calibration unit is the country, or its 10-degree squares where they lower the held-out error per 1-degree tile and month by more than 0.2 points without raising the error per country and month (`choose_units`, `assign_units` in `pipeline/world.py`). Reference values, written on 2026-11-15: 235 countries, 128 checked (99.8% of the fire cell-days), 107 on a borrowed calibration, 45 on squares; error per month 3.8% in the Democratic Republic of the Congo, 3.5% in Brazil, 4.8% in Russia; world sensor jump 2.58x raw to 0.94x harmonized. Two runs of `pipeline.world` give identical `harmonized.parquet`, `calibration.json` and report (checked 2026-11-15); a change that moves these numbers needs an explanation in the PR.
- A cell on a border has one row per country in the world's `harmonized.parquet`; sum them. The API and the web app do not serve `data/world/` yet: the trust block is keyed by region name and `/api/cells` returns every cell.
- Both series in the API are in fire cell-days: `harmonized` from `n_harmonized`, `raw` from `n_raw` of `data/agg/harmonized.parquet`. Only when that file is missing does `raw` fall back to hotspot counts; the API reports the unit of each series (`unit`, `units`) and the web app prints it, so never hard-code a unit in the UI.
- What was tried, adopted and left out is listed in `docs/METHOD.md`; the code is in `research/experiments/` and `research/harmonize_ml/` (the boosted weight and the context model are adopted where they win per country; the rest is not). Read that list before proposing a "smarter" model.
